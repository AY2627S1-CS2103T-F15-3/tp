UniMate User Guide

UniMate helps university students organise contacts by major, class year and tags. It is a desktop application for managing contacts, optimized for use through a Command Line Interface (CLI) while retaining the benefits of a Graphical User Interface (GUI). If you type quickly, UniMate can help you manage contacts faster than traditional GUI applications.

This guide describes Unimate v1.5.

Quick start

Run only one instance of UniMate at a time. Running multiple instances simultaneously is unsupported and may overwrite saved changes.

  1. Ensure that Java 25 is installed on your computer. Mac users: Ensure you have the precise JDK version prescribed here.

  2. Download the v1.5 unimate.jar, once published, from the UniMate releases page.

  3. Copy the file to a writable folder you want to use as the home folder for UniMate.

  4. Open a terminal, cd to the folder containing the JAR file, and run java -jar unimate.jar.
    A GUI similar to the one below should appear in a few seconds. Note how the app contains some sample data.

  5. Type a command in the command box and press Enter to execute it. For example, type help and press Enter to open the help window.
    Some example commands you can try:

    • list : Lists all contacts.

    • add n/John Doe p/98765432 e/johnd@example.com a/John street, block 123, #01-01 : Adds a contact named John Doe to UniMate.

    • delete 3 : Deletes the 3rd contact shown in the current list.

    • undo : Reverts the most recent change to your contacts.

    • clear : Deletes all contacts.

    • exit : Exits the app.

  6. Use the Command summary below for a quick reference, or see Features for detailed instructions.

Using the contact list

Contact details appear in two columns when the window is wide enough. In a narrow window, the academic fields move below the phone, address and email fields.

  • Long names and field values show ... when they cannot fit. Click a shortened value to expand it, then click again to collapse it. This also applies to shortened tags.
  • Use the scrollbar on the right of the contact list to reach other contacts or the bottom of an expanded card. Drag the thumb or use its arrow buttons for smaller movements.
  • Expanding a value changes only its display; the saved contact details remain unchanged.
  • Expanded values stay open while scrolling or resizing. Changing a contact resets its expanded values; restarting the app also resets expansion. A command that leaves the contact unchanged keeps its expansion state.

Keyboard navigation

Expandable values, including long tags, have an orange dotted outline when focused. Their order is: name, tags from left to right, phone, address, email, major, class year, last updated. Up/Down in the command box still recalls command history. Plain Tab and Shift+Tab never enter the message area; use Ctrl+Tab for that. The Ctrl+Tab route works on macOS, Linux and Windows. Clicking inside the message area also focuses it.

Caution: The message area does not show an outline or highlight when it has focus, so nothing on screen changes when Ctrl+Tab moves focus there.

  • To check where focus is, press Down: if the message text scrolls, the message area has focus.
  • Typing does nothing while the message area has focus. Press Ctrl+Shift+Tab, or click the command box, before typing your next command.

Features

Notes about the command format:

  • Command words are case-insensitive: tag, TAG and Tag select the same command. This applies to all commands.
    Parameter prefixes remain case-sensitive: use t/, not T/. Command arguments retain their original capitalization; Fixed sorting keywords also ignore case: SORT Name ASC works like sort name asc.

  • Words in UPPER_CASE are the parameters to be supplied by the user.
    For example, in add n/NAME, replace NAME with a value such as John Doe.

  • Items in square brackets are optional.
    For example, n/NAME [t/TAG] can be used as n/John Doe t/friend or as n/John Doe.

  • Items followed by ... can appear zero or more times.
    For example, [t/TAG]... may be omitted, or written as t/friend or t/friend t/family.

  • Prefixed parameters can be in any order. For sort, the field must precede the direction.
    For example, if the command specifies n/NAME p/PHONE_NUMBER, p/PHONE_NUMBER n/NAME is also acceptable.

  • Extraneous parameters for help, exit, and clear are ignored.
    For example, help 123 is interpreted as help.

  • list, listfav, tags, undo and redo take no parameters and reject extra arguments.
    In particular, list all is rejected; use plain list to show all saved contacts. See Listing all persons for details.

  • If you are using a PDF version of this document, be careful when copying and pasting commands that span multiple lines as space characters surrounding line-breaks may be omitted when copied over to the application.

Viewing help: help

Shows a message explaining how to access the help page.

Format: help

  • The help window shows the User Guide's web address and a Copy URL button. It opens and copies the address even without an internet connection.
  • Opening the copied address in a web browser needs an internet connection.
  • Offline use was tested on macOS, Linux and Windows, and works as described.

Adding a person: add

Adds a person to UniMate.

Format: add n/NAME [p/PHONE_NUMBER] [e/EMAIL] a/ADDRESS [m/MAJOR] [c/CLASS_YEAR] [f/] [t/TAG]... [d/DEFAULT_INDEX]...

Field rules

Field Accepted value
Name n/ Required. English letters, digits and spaces; must not be blank.
Address a/ Required, non-blank text. See the prefix warning below.
Phone p/ Optional. At least three digits, without spaces, + or punctuation.
Email e/ Optional. local-part@domain; letters and digits with separated +, _, . or - in the local part, never at either end. Domain labels use letters/digits with separated internal hyphens; the final label has at least two characters. A final label containing a hyphen must have at least two letters/digits on one side of a hyphen (a@x.ab-c is accepted; a@x.y-z is rejected).
Major m/ Optional, non-blank text on one line.
Class year c/ Optional. Four digits from 2000 to 2099.
Tag t/ Optional. English letters and digits, without spaces. Repeat the prefix for multiple tags.

Omit an optional field when unknown; do not supply an empty value in add.

For example, add n/Alex Tan a/NUS m/Computer Science c/2027 creates a contact without a phone or email. Use a name that is not already saved.

Tip: A person can have any number of tags, including zero. Major and class year are optional and can be supplied independently.

Check your field prefixes: Use the prefixes shown in the command format above. Unknown prefix-like text can become part of the preceding field instead of producing an error. For example, add n/PrefixProbe a/NUS x/typo saves the address as NUS x/typo; x/ does not start a separate field.

Recognised prefixes start a new argument when preceded by a space, even within text intended as an address. In add, f/ is a recognised flag: add n/Alice a/Block f/ saves the address as Block and marks Alice as a favourite. add n/Alice a/Block f/3 is rejected because the flag has a value. Without a space before f/, add n/Alice a/Blockf/3 saves the full address Blockf/3 and does not mark Alice as a favourite. A space followed by f/ is reserved for the flag and cannot be included as literal address text in add.

Check the added contact's details. To correct the PrefixProbe example, run find PrefixProbe, confirm the displayed contact, then edit 1 a/NUS.

  • Supply each single-value field only once. Leading and trailing spaces around values are ignored.
  • The fields are saved with the contact, can be edited using edit, are shown in the displayed contact list and appear in command messages when specified.

Duplicate names

  • Names match ignoring case: John Doe and john doe are duplicates even if other details differ. Original capitalization is retained; editing a contact's own name capitalization is allowed.
  • A duplicate error shows the existing contact's saved details. A displayed index refers to its current card. A saved index means the contact is hidden: run list, then sort reset, and check the card before using that index. list alone retains the current sort order.
  • Rejecting a duplicate leaves the current view, saved contacts and undo/redo history unchanged.
  • Before opening an older data file, back it up. Give contacts whose names differ only in case distinct names; they are not automatically merged or renamed. See data-file recovery before continuing after a loading error.
  • A successful add can be reverted with undo.

Favourite status

  • Include f/ to create the contact as a favourite immediately, with a red heart beside their name. The flag takes no value, may appear anywhere among the prefixed fields, and may appear only once. Inputs such as f/true and f/false are rejected. Omit f/ to create a contact without favourite status. Favourite status is saved with the contact and included in the same undo/redo step as the addition. The success message begins New favourite contact added: when f/ is supplied, or New person added: otherwise. A flag with a value reports The f/ flag does not take a value. Use f/ alone to mark the new contact as a favourite.
  • After creation, use fav INDEX or unfav INDEX to change favourite status. edit preserves the current favourite status and cannot change it.
  • Phone and email are independently optional. Omit p/ or e/ when unknown; do not supply an empty prefix in add. Non-empty values must satisfy the existing phone and email format rules. A contact without either receives the automatic incomplete reminder.

Shared contact details

  • A different name with a shared phone number or email is added successfully. An amber advisory follows the normal success message, for example: Warning - duplicate details detected: #2 Alice (phone); #3 Bob (email). All matches are listed with their names, current indices and shared fields; scroll to read long feedback.
  • Non-empty phone numbers match exactly; emails match ignoring case. Empty values are ignored. Shared details do not merge contacts or change the duplicate-name rule.
  • Adding shows the full contact list and retains sorting. Warning indices refer to this refreshed list, including contacts hidden by the previous filter. One undo removes only the newly added contact.

Examples:

  • add n/Alice p/91234567 a/NUS f/ creates Alice as a favourite; listfav includes Alice immediately.
  • add n/Alex Tan p/91234567 e/alex@example.com a/10 Kent Ridge Road m/Computer Science c/2027 t/classmate
  • add n/John Doe p/98765432 e/johnd@example.com a/John street, block 123, #01-01
  • add n/Betsy Crowe t/friend e/betsycrowe@example.com a/Newgate Prison p/1234567 t/criminal
  • After adding Alex Tan above, add n/Study Partner p/91234567 a/NUS adds the new contact and warns that Alex Tan shares its phone number. One undo removes the newly added Study Partner.

Automatic incomplete reminders

UniMate shows an amber incomplete reminder when both phone and email are missing, so you can identify contacts without a recorded way to reach them. This is automatic: there is no incomplete command.

Phone Email Reminder
Present Present None
Present Missing None
Missing Present None
Missing Missing incomplete

Address, major, class year, tags and notes do not affect this check. Missing phone and email values appear as Not specified on the contact card. A supplied phone still requires at least three digits; non-empty email values retain the existing email format requirements.

Adding and clearing contact details

  • add n/Alice a/NUS creates a contact without a phone or email and shows the reminder (assuming Alice does not already exist).
  • add n/Bob a/NUS p/91234567 records a phone only and has no incomplete reminder.
  • edit 1 p/91234567 or edit 1 e/alice@example.com supplies a contact method and removes the reminder immediately.
  • edit 1 p/ clears the phone; edit 1 e/ clears the email. edit 1 p/ e/ clears both, causing the reminder to appear. Omitted fields retain their values. As with the existing optional academic fields, empty prefixes clear fields only in edit; add n/Alice a/NUS p/ is rejected.
  • An actual contact-detail change refreshes lastUpdated and clears any outdated update reminder. If both contact methods are cleared, incomplete still appears even though the profile date is now current. Entering unchanged values does not reset the date.

GUI and custom tags

Reminders use amber text on a dark brown background. Ordinary tags are grey, and favourite hearts remain red. update and incomplete may appear together, once each, when their independent conditions apply.

  • System reminders are not saved as ordinary tags. Removing a user tag with untag cannot remove the date-based or incomplete reminder.
  • An existing custom tag named incomplete remains saved under its original name and is displayed as a grey tag labelled incomplete (custom); manage it using t/incomplete.
  • It can coexist with the amber reminder, just as update (custom) can coexist with update.

Phone/email values are saved normally. Older JSON files with valid contact details remain compatible; absent, null or empty phone/email fields are treated as unspecified. Other required fields and non-empty contact-value validation remain unchanged.

Tracking a contact's latest update date

Use this date to check how recently a contact's basic information was maintained. Run list and look for Last updated below Class year on each card, as shown in the Quick start screenshot. The date is visible even without an update reminder. Hover over the date for an explanation of what it records.

Dates use YYYY-MM-DD: for example, 2026-10-20 means 20 October 2026. UniMate records the date automatically using your computer's local date; there is no command parameter for setting it yourself.

Action Effect on the contact's date
Successfully add a new contact Records today's date.
Edit the name, phone, email, address, major or class year to a different value Records today's date. Clearing a previously specified optional field also counts.
Re-enter the same values, or submit a command that is rejected before changing a contact Keeps the previous date.
Change only tags, notes or favourite status Keeps the previous date. These are your annotations, rather than changes to basic contact information.
View, search, filter or sort contacts Keeps the previous date.
Undo or redo a contact change Restores the date belonging to that contact state, rather than recording the date of the undo or redo.

The date has day precision, so several changes on the same day show the same date. Once saving succeeds, it remains available when you reopen UniMate from the same folder.

Example: run list and identify the contact's current displayed index. Enter edit 1 p/91234567, replacing 1 with that index. If that contact's phone changes, its card immediately shows today's date. If the phone was already 91234567, the previous date remains.

Contacts from older files without a recorded date show Last updated: Unknown. This means no date was saved; it does not mean the contact was updated today. The date stays unknown after reopening until you actually change one of the basic fields above.

To review your collection, use update-date sorting: sort updated asc puts the oldest known dates first, while sort updated desc puts the newest first. Unknown dates stay last in both directions. The separate update reminder flags contacts whose known dates are over a calendar year old.

Automatic update reminders

UniMate automatically reminds you to check a contact whose basic information has not been updated for more than one calendar year. No new command or manual tag is required.

  • An amber update label on a dark brown background appears beside the contact's grey ordinary tags. Favourite hearts remain red.
  • The reminder is calculated from the contact's saved lastUpdated date. Exactly one year does not trigger it: if today is 2026-10-18, a date of 2025-10-18 has no reminder, while 2025-10-17 does.
  • New contacts start with today's date. Successfully changing the name, phone, email, address, major or class year through edit records today's date and removes the reminder. For example, edit 1 p/98765432 clears the reminder if it changes the first displayed contact's phone number.
  • Entering the same basic values again, editing only tags, changing notes, or using tag, untag, fav, unfav, list, listfav or find does not reset the date.
  • Reminders are checked when cards are loaded or refreshed. Successful commands refresh the list; no background timer runs while the app is idle. The date is saved with the contact and retained across restarts. Undo and redo restore the recorded contact state, including its date.

System reminders and custom tags

The amber update reminder is generated from the date and is never added to your ordinary tag collection. You cannot permanently remove it with untag; update the contact's basic information instead.

A custom tag named update is still supported and saved unchanged.

  • It appears as a grey update (custom) tag to distinguish it from the amber system reminder.
  • Use t/update to manage that custom tag as before.
  • Adding or removing it does not create, overwrite or clear the system reminder.
  • Both can be displayed together without duplicate system reminders.

Older data files

Missing or null lastUpdated values remain unknown after saving and restarting. An unknown date does not generate an age-based update reminder. A supplied invalid date is rejected rather than silently replaced.

Format: tags

Adding tags to a person: tag

Adds default or custom tags to an existing person without replacing their existing tags.

Format: tag INDEX [d/DEFAULT_INDEX]... [t/TAG]...

Parameters

  • INDEX is the person's position in the currently displayed list, including results from find. It must be a positive integer from 1 to 2147483647 and refer to a displayed person. Signs such as +1, zero, negative values and decimals are not accepted.
  • d/DEFAULT_INDEX selects a default tag from 1 to 5: Friend, Classmate, Teammate, Tutor, Prof, respectively. Use the tags command to view this list. The same integer syntax rules apply.
  • t/TAG supplies a non-empty custom tag name containing only English letters (A-Z, a-z) and digits (0-9). Spaces within a name and punctuation are not allowed. Leading and trailing whitespace is trimmed.
  • At least one d/ or t/ value is required. Both prefixes can be repeated and mixed in any order after INDEX. Separate each prefix from the preceding argument with a space.

Examples (assuming at least one person is displayed):

  • tag 1 d/2 adds Classmate to the first displayed person.
  • tag 1 d/1 d/3 adds Friend and Teammate.
  • tag 1 t/NOC appends NOC without removing existing tags.
  • tag 1 t/NOC t/CCA d/2 appends two custom tags and Classmate.

Expected behaviour

  • The selected person's tags are updated; their other details and the current list filter are preserved.
  • The result message starts with Tagged person: , followed by the person's name, phone, email, address, any specified major and class year, and updated tags. Tag display order is not guaranteed.
  • Repeated tags and tags already attached to the person are stored only once. Adding an existing tag still returns the success message.
  • Tag names retain their original capitalization and are case-sensitive: NOC and noc are different tags, even though command words are case-insensitive. This preserves existing user-defined categories without merging or changing stored tags. Default tags are stored by name in the same collection as custom tags: d/1 and t/Friend select the same tag, whereas t/friend is different.
  • Custom tags still use t/ in add and edit. Unlike tag, edit INDEX t/TAG replaces the entire tag set.

Error handling

Input or situation Result message
Missing tags (tag 1), missing index, or invalid index syntax (tag 0 t/NOC, tag x t/NOC) Invalid command format!, followed by the tag usage instructions.
A valid positive index outside the displayed list, with otherwise valid input The person index provided is invalid.
Empty, non-integer or out-of-range default index (tag 1 d/, tag 1 d/6) Default tag index must be an integer from 1 to 5. Use tags to view them.
Empty or invalid custom tag (tag 1 t/, tag 1 t/NOC!, tag 1 t/two words) Tag names should be alphanumeric

These input errors leave all contacts unchanged. If any supplied tag is invalid, none of the tags in that command are added. Use only d/ and t/; unsupported prefixes are not ignored and may cause an index or tag validation error.

Viewing long tag names

Tag names longer than 20 characters initially show their first 20 characters followed by .... Click a tag to expand or collapse its full name inside the card. You can also hover over it to see the complete name in a tooltip; move the pointer away to close it. Tags may be shortened further when space is limited.

This affects display only: the stored tag name and validation rules are unchanged. Use the complete original name with tag, untag or tag filtering, rather than the abbreviated display text. Custom tags that share a system-reminder name retain their (custom) marker.

Removing tags from a person: untag

Removes specified tags from an existing person while preserving all other tags and contact details.

Format: untag INDEX t/TAG [t/TAG]...

Parameters

  • INDEX identifies a person in the currently displayed list and follows the same positive integer rules as tag.
  • At least one non-empty t/TAG is required. Names must contain only English letters and digits; leading and trailing whitespace is trimmed. Names are matched exactly, including case.
  • Place INDEX first and separate each t/ prefix from the preceding argument with a space. Repeat t/ to remove multiple tags.
  • untag does not accept d/. To remove a default tag, use its name, such as t/Friend.

Examples (assuming at least one person is displayed):

  • untag 1 t/NOC removes NOC while keeping the person's other tags.
  • untag 1 t/NOC t/CCA removes both tags.
  • untag 1 t/Friend removes the default tag Friend by name.

Expected behaviour

  • The result message starts with Untagged person: , followed by the person's name, phone, email, address, any specified major and class year, and remaining tags. Tag display order is not guaranteed.
  • The current list filter is preserved. Removing the last tag leaves the person with no tags; it does not delete the person.
  • Repeated names and tags the person does not have are ignored. The command still returns the success message, even if no tags were removed. For example, untag 1 t/noc does not remove NOC.

Error handling

Input or situation Result message
Missing tags (untag 1), missing index, or invalid index syntax (untag 0 t/NOC) Invalid command format!, followed by the untag usage instructions.
A valid positive index outside the displayed list, with otherwise valid input The person index provided is invalid.
Empty or invalid tag (untag 1 t/, untag 1 t/NOC!) Tag names should be alphanumeric
Unsupported default index syntax (untag 1 d/1) Invalid command format!, followed by the untag usage instructions.
Unsupported prefix after a tag (untag 1 t/NOC d/1) Tag names should be alphanumeric

These input errors leave all contacts unchanged. If any supplied tag is invalid, none of the tags in that command are removed. Unlike edit 1 t/, untag 1 t/ does not clear the tag collection.

For both commands, UniMate saves the updated data automatically. A saving failure reports one of:

  • Could not save data due to the following error: ...
  • Could not save data to file ... due to insufficient permissions to write to the file or the folder.

If the tags changed, the message adds that the change has been applied but not saved to the local data file. The error does not mean the change was rolled back. See Saving the data.

A tag or untag that changes a person's tags can be undone and redone. Adding a tag the person already has, or removing one they do not have, changes nothing and does not create an undo step.

Marking a favourite contact: fav

Marks a person in the currently displayed list as a favourite.

Format: fav INDEX

  • INDEX must be a positive integer from 1 to 2147483647 and refer to a person in the currently displayed list. Zero, negative numbers, a leading +, decimals and extra arguments are not accepted.
  • The person's other details, tags, major and class year are preserved, together with the current list filter.
  • A successful command shows Added to favourites: followed by the updated person's details.
  • A favourited contact displays a red heart (♥) beside their name. The icon is a visual indicator; use fav or unfav to change the status.
  • Favourite status is saved automatically and retained after restarting UniMate. New contacts start as not favourited unless f/ is included in add. Contacts loaded from older files without favourite status start as not favourited.
  • Marking a favourite can be undone and redone.

Example (assuming at least one person is displayed):

  • fav 1 marks the first displayed person as a favourite and immediately shows the circular heart.

Error handling

Input or situation Result message
Missing or invalid index, or extra arguments (e.g., fav, fav 0, fav 1 extra) Invalid command format!, followed by the fav usage instructions.
Index exceeds the displayed list size The person index provided is invalid.
Person is already favourited The selected contact's name followed by is already a favourite., e.g., Alice is already a favourite.

These errors leave contact data unchanged.

Removing favourite status: unfav

Removes favourite status from a person in the currently displayed list.

Format: unfav INDEX

  • INDEX follows the same rules as fav.
  • A successful command shows Removed from favourites: followed by the person's details, and the circular heart disappears immediately.
  • All other contact fields are preserved. The updated favourite status is saved automatically and remains removed after restarting UniMate.
  • When viewing favourites using listfav, the person immediately disappears from that filtered view. The contact remains stored and can be seen again using list.
  • Removing favourite status can be undone and redone.

Example (assuming the first displayed person is favourited):

  • unfav 1 removes favourite status from that person.

Error handling

Input or situation Result message
Missing or invalid index, or extra arguments (e.g., unfav, unfav -1, unfav 1 extra) Invalid command format!, followed by the unfav usage instructions.
Index exceeds the displayed list size The person index provided is invalid.
Person is not favourited The selected contact's name followed by is not a favourite., e.g., Alice is not a favourite.

These errors leave contact data unchanged. After unfav removes a person from the favourite list, check the new displayed indices before entering another indexed command.

Listing favourite contacts: listfav

Shows all favourited contacts in their existing order, with displayed indices starting at 1. This replaces the previous search or list filter. Other contacts are hidden from the view, not deleted or modified.

Format: listfav

  • No arguments are accepted. For example, listfav 1 shows Invalid command format! followed by the listfav usage instructions, and leaves the current view unchanged.
  • When favourites exist, the result is Listed N favourite contact(s)., where N is the number shown. Contact details and circular heart icons remain visible.
  • If there are no favourites, the list is empty and the result is No favourite contacts found.

Switching between lists

  • The existing AB3 list command shows all contacts. The new listfav command shows only favourites. Both change the view without changing contact data or favourite status.
  • fav INDEX and unfav INDEX always use the indices in the current view, including search results and the favourite list. A displayed index is not a permanent contact identifier.
  • For example, run list, then fav 1, then listfav. Run unfav 1 to remove the first person shown in the favourite list, then list to see all contacts again.
  • The existing add and edit commands restore the full list after success. Run listfav again to return to favourites. Tag and untag operations preserve the current filter and favourite status.

Adding or replacing a contact's note: note

Saves one note for an existing contact. Saving another note replaces its text; new contacts start without a note.

Format: note INDEX TEXT

  • Use the positive INDEX in the current displayed list, including search, filter and favourite results.
  • TEXT must contain non-whitespace text on one line, with at most 500 characters. Unicode text and punctuation are allowed.
  • The command box is a single line, so it removes tabs and line breaks from pasted text before you press Enter. For example, pasting Left, a tab, then Right saves LeftRight, not an error. Check the text in the command box before submitting, and type a space where you want one.
  • Surrounding whitespace, including non-breaking spaces, is trimmed before checking the length. Spaces within the note are preserved.
  • Everything after the index is saved as text, including prefixes such as n/ and t/. No quotation marks are needed.
  • Other contact details, the filter and sort order are preserved. Notes are saved automatically and remain available after restarting UniMate.

Example: note 2 Met during CS2103T

Feedback includes the saved text. Replacing Alice's existing note with note 2 Met at hackathon, where Alice is the second displayed contact, shows:

Note replaced for Alice. Use undo to restore the previous note.
Previous note: Met during CS2103T
Saved note: Met at hackathon

Adding or replacing a note supports undo and redo. Saving identical text reports Note unchanged for NAME. and creates no undo step or change to redo history.

A small orange icon at the card's top right indicates a saved note. Use shownote to read it; scroll vertically in the message area to read long feedback. With the keyboard, press Ctrl+Tab to focus the message area (see Using the contact list). The message area shows no focus outline, so press Ctrl+Shift+Tab to return to the command box before typing.

Viewing a contact's note: shownote

Displays the contact's note in the message area.

Format: shownote INDEX

Example: shownote 2

The message starts with Note for NAME:, followed by the saved text. An empty note reports No notes have been added to this contact. This preserves contact data, the current view and undo/redo history.

Deleting a contact's note: delnote

Removes the note from a contact while retaining the contact and all its other details.

Format: delnote INDEX

Example: delnote 2

The message Note deleted for NAME. appears and the note icon disappears. The filter and sort order are preserved. Use undo or redo to reverse or repeat the deletion.

If the note is already empty, This contact has no note to delete. appears; contact data and history stay unchanged.

All three note commands require an index in the displayed list. Invalid input leaves contacts and history unchanged. shownote and delnote accept only an index; use delnote, rather than an empty note, to clear text.

Listing all persons: list

Use list to view previously added contacts or return to your full collection after a search or filter. It displays every contact currently saved in UniMate, including contacts loaded when you reopen the app. Each contact card includes the person's name, tags, phone number, address, email address, major, class year and latest update date. Optional academic fields that have no saved value are displayed as Major: Not specified or Class year: Not specified.

Format: list

  • list takes no parameters. Leading and trailing whitespace is accepted, but list all, list 1 and list t/Friend show Invalid command format! followed by usage instructions. A rejected command leaves the view unchanged.
  • Replaces a find, filter or listfav view with the full saved contact list. Contacts hidden by those views are shown again with displayed indices starting at 1; deleted contacts are not recovered.
  • Retains the active sort order. Without an active sort, contacts appear in their saved order. Check the displayed indices again before using an indexed command such as edit or delete.
  • Lists all saved contacts; it does not provide a recently added view or sort contacts by their creation date.
  • The result starts with Listed all persons. and reports N person(s) listed! on the next line, where N is the total number of contacts displayed. An empty address book succeeds with 0 person(s) listed!. The status above the cards shows Showing N of N contacts and Filter: All contacts, followed by the current sort order.
  • Viewing contacts does not change their details, recorded update dates or undo/redo history. Saved contacts remain available after restarting UniMate from the same folder; active searches, filters and sort choices are temporary.

Examples (enter each command separately):

Commands What to expect after list
find Alex, then list Every saved contact returns, even if the search found no matches. The reported count is the full collection size.
listfav, then list Non-favourites appear alongside favourites; favourite hearts are preserved.
sort name asc, then filter m/Computing, then list All saved contacts appear in ascending name order; the major filter is cleared.

For a long collection, scroll through the cards. If a value ends in ..., click it to read the full value. See Using the contact list for the layout and keyboard controls.

Editing a person: edit

Edits an existing person in UniMate.

Format: edit INDEX [n/NAME] [p/PHONE] [e/EMAIL] [a/ADDRESS] [m/MAJOR] [c/CLASS_YEAR] [t/TAG]...

For example, edit 1 m/Mathematics changes only the first displayed contact's major. See the shared field rules for accepted values.

Input Effect
Omit a prefix Keep its existing value.
p/, e/, m/ or c/ with no value Clear that optional field.
Supply one or more t/TAG values Replace the entire tag set. Use tag to add without replacing.
t/ with no value Remove all ordinary tags.

Name and address cannot be cleared. Supply at least one field; edit INDEX alone is invalid.

  • INDEX is the positive index in the current displayed list.
  • Supply each single-value prefix only once.
  • Leading and trailing spaces are ignored. If any supplied value is invalid or an academic prefix is repeated, no fields are updated.
  • After a successful edit, the full contact list is shown while retaining the active sort order. If editing search or filter results, run find or filter again before using a result index for another edit.
  • When the supplied t/ values change the tag set, feedback includes Tags replaced. Removed: ... . Added: ... . with actual changes sorted by tag name (None for an empty list). Unchanged tags are excluded. For example, replacing Friend and Classmate with Project reports Tags replaced. Removed: Classmate, Friend. Added: Project. Use tag to add tags while keeping existing tags.
  • Email local parts allow letters, digits and + _ . -. Special characters cannot be consecutive or at either end: alice++cs2103t@example.com is rejected; alice+cs2103t@example.com is valid. Email errors show each rule on a short line, including the consecutive-special-character rule. Feedback wraps within the result display when the window is narrow.
  • Clearing both phone and email shows the automatic incomplete reminder.
  • A successful edit that changes the person's details can be reverted with undo. Undo/redo messages retain the full Edited person: ... contact details without repeating the field or tag change summary or duplicate-details warning.
  • The result display shows Edited NAME: followed by only the fields that actually changed, one per line in the form Field: old value → new value. Cleared optional fields show Not specified. Fields whose supplied values already match are omitted. Tag changes use the removal/addition summary above. The command box is cleared, and the contact card shows the resulting details.
  • If all supplied values already match, the result is No changes made to NAME. The supplied values match the existing details. The contact's update date and undo/redo history are preserved; no undo step is created and available redo remains available. The full contact list is still shown and the command box is cleared.
  • Changing a phone number or email to one used by another contact keeps the field change summary and appends a line such as Warning - duplicate details detected: #2 Alice (phone); #3 Bob (email). Tag changes, when present, appear before the warning. The complete feedback is amber and scrollable; indices refer to the refreshed full list, including previously hidden contacts.
  • Warnings check only changed, non-empty contact methods: phone matching is exact and email matching ignores case. Unchanged values, email-capitalization-only changes and cleared fields do not trigger warnings. The edit is saved normally; undo/redo does not repeat the advisory.
  • Notes and favourite status are preserved. Use fav INDEX or unfav INDEX to change favourite status; it cannot be changed with edit. Changing a basic profile field refreshes the contact's update date; changing only tags does not refresh that date.
  • Invalid input, an index outside the displayed list, or a name already used by another contact leaves the contacts and current view unchanged. The result display shows the error and the command box keeps the input for correction.

If saving fails, the result display reports a saving error and keeps the command text. The in-memory edit has already happened; the error does not mean it was rolled back.

Examples:

  • edit 1 p/91234567 e/johndoe@example.com Edits the phone number and email address of the 1st person to be 91234567 and johndoe@example.com respectively.

  • edit 1 m/Computer Science c/2027 Updates the 1st person's major and graduation year.

  • edit 1 m/ c/ Clears both academic fields while keeping the other details. If Alice Tan previously had major Computer Science and class year 2027, feedback is:

    Edited Alice Tan:
Major: Computer Science → Not specified
Class year: 2027 → Not specified

    Repeating the command reports No changes made to Alice Tan. The supplied values match the existing details.

  • edit 1 e/ALICE@example.com changes alice@example.com to the supplied capitalization. Feedback includes Email: alice@example.com → ALICE@example.com and the profile date is refreshed. Email matching ignores case, so this capitalization-only edit does not introduce a shared-email warning.

  • edit 2 n/Betsy Crower t/ Edits the name of the 2nd person to be Betsy Crower and clears all existing tags.

Locating persons by name, major or class year: find

Finds contacts by name, major or class year.

Format: find KEYWORD [MORE_KEYWORDS]...

  1. Type at least one word to search for. Separate words with spaces.

    • find on its own shows an error, and the list stays the same

  2. Capital letters do not matter.

    • hans is the same as Hans

  3. Only names, majors and class years are searched. Phone numbers, emails, addresses, tags and notes are not.

    • find friends does not find a contact tagged friends. Use filter t/friends instead.

  4. Only whole words match.

    • Han does not find Hans
    • Comp does not find Computer Science
    • 27 does not find the class year 2027

  5. Punctuation counts as part of a word.

    • for the major Computer Science (Hons), find Hons finds nothing, but find (Hons) works

  6. A contact is shown if it matches any of your words. The order of your words does not matter.

    • find Hans Bo shows both Hans Gruber and Bo Yang
    • find Computer Science also shows contacts majoring in Data Science

  7. Do not type prefixes such as n/ or m/. They are treated as part of the word.

    • find n/Alex usually finds no one

  8. Contacts with no major or class year cannot be found by those fields. Searching for Not specified does not find them.

  9. Every search looks through all your contacts, not just the ones on screen.

    • it replaces the results of your previous find, filter or listfav
    • your sort order is kept

  10. UniMate shows how many contacts were found, such as 2 person(s) listed!. The line above the list shows what you searched for.

    • Filter: Search: alex OR david

  11. The results are numbered from 1. Use these numbers in commands such as edit, delete and fav.

    • run list to see all your contacts again

  12. Searching never changes your contacts, so it does not affect undo or redo.

Examples:

  • find John shows john and John Doe
  • find Computer Science shows contacts majoring in Computer Science, Computer Engineering or Data Science
  • find 2027 shows contacts in the class of 2027
  • find alex david shows Alex Yeoh and David Li

Tip: To show only contacts whose major is exactly Computer Science, use filter m/Computer Science instead.

Filtering contacts by major, class year and tag: filter

Shows contacts whose complete field values match all supplied criteria (AND matching).

Format: filter [m/MAJOR] [c/CLASS_YEAR] [t/TAG]

  • Supply at least one criterion. Each prefix may appear only once, in any order, separated by spaces.
  • Major and tag matching ignore case but require the complete value: m/Computer Science matches Computer Science, while m/Computer does not. A tag criterion matches any one of the contact's tags.
  • Class year matches exactly and must be four digits from 2000 to 2099.
  • Omitted criteria leave those fields unrestricted. An unspecified academic field does not match a supplied criterion for that field, but the contact can still match a criterion on another field.
  • Leading and trailing spaces around values are ignored; spaces within a major remain significant.
  • Only m/, c/ and t/ start filter criteria. Other prefix-like text within a major is part of its value: filter m/Mathematics w/ Computing matches that complete major. Check your prefixes carefully; for example, filter m/Computing x/value searches for the literal major Computing x/value.
  • Blank values, repeated criteria, unexpected text before the first criterion and invalid values produce an error without changing the current results. Use t/Friend to filter a default tag; d/ does not select a default tag in a filter.
  • The result message shows the number of matching contacts. Zero matches displays an empty list; no contacts are deleted.
  • A persistent status line above the contact list shows the displayed/total contact counts, active filter or search, and sort order. For example: Showing 3 of 20 contacts | Filter: Class year: 2027 | Sort: Name ascending. It stays visible when another command, such as shownote, replaces the result message. Long criteria wrap onto additional lines. The status also identifies favourites views and empty results. Very long search or filter criteria can hide the contact list; see Window and display limitations for recovery steps.
  • Each filter replaces the previous search or filter and retains the active sort order, or the saved contact order if no sort has been chosen. find replaces the filter; list shows all contacts again.
  • Indices refer to the currently displayed list. For example, delete 1 targets the first filtered result. Deleting or untagging a contact that no longer matches removes it from the results and renumbers the list.
  • Successful add, edit, undo and redo commands show the full list. Reapply the filter before using a filtered index again. Tag and untag retain the active filter.
  • Filters are temporary: restarting UniMate shows the full contact list. Filtering does not create an undoable data change or clear redo history.

Examples:

  • filter m/Computer Science c/2027 t/Classmate shows contacts who match all three criteria.
  • filter c/2027 shows all contacts with class year 2027, regardless of their major or tags.
  • filter t/friend shows contacts with a complete tag matching friend, ignoring case.
  • list returns to the full contact list.

Unlike find Computer Science, which searches for either word across names and academic fields, filter m/Computer Science checks only the complete major value.

Sorting contacts by name, major, class year or update date: sort

Orders the displayed contacts while keeping the current search or filter.

Format: sort FIELD DIRECTION or sort reset

  • To choose a sort order, both arguments are required and must appear in this order. Keywords are case-insensitive; for example, sort Name ASC is accepted. Extra surrounding spaces and spaces between arguments are allowed.

    Argument Accepted values Meaning
    FIELD name, major, year, updated Full name, full major, graduation year or latest update date
    DIRECTION asc, desc A–Z / earliest first, or Z–A / latest first

  • Names and majors are compared case-insensitively. Class years and update dates are ordered chronologically. For updated, asc puts the oldest dates first and desc puts the newest dates first. Contacts with the same date use ascending, case-insensitive name order in both directions. Contacts with unknown update dates stay last in both directions.

  • Contacts with an unspecified major or class year appear last when sorting by that field, for both directions. Equal academic values, including unspecified values, use ascending name order. Names differing only in case compare equally.

  • sort reset removes the active sort and restores saved contact order, while keeping the current search or filter. It takes no direction or other arguments and succeeds even if no sort is active. Unlike sort reset, list removes the filter and keeps the current sort. Use list, then sort reset, to show all contacts in saved order.

  • Sorting an empty list or a single contact succeeds. Sorting does not add or remove contacts.

  • filter, find and list retain the chosen sort order. A successful add, edit, undo or redo shows all contacts in that order; tag, untag and delete retain the current filter and sort. Changing a sorted field can move a contact to a new position.

  • Numbered commands use the currently displayed order. Check the latest card numbers before using edit, delete, tag or untag; sorting and contact changes can renumber the list.

  • Missing arguments, unsupported fields or directions and extra arguments produce a usage error without changing the current results or saved data.

  • Sorting is temporary. It does not reorder saved contacts, create an undoable change or clear redo history. Restarting restores the saved contact order and shows all contacts.

Examples:

  • sort name asc displays names from A to Z.
  • sort major desc displays majors from Z to A, with unspecified majors last.
  • sort updated asc brings contacts whose basic information has not changed for the longest time to the top. sort updated desc shows the most recently added or updated contacts first. Several updates on the same day share a date; this does not order individual changes within that day.
  • filter c/2027, then sort name asc, then sort reset shows only class year 2027 contacts in saved order. The status changes from Sort: Name ascending to Sort: Saved order.
  • filter t/Classmate, then sort year asc, shows only classmates, earliest class year first. list then shows all contacts in the same year order.

Deleting contacts: delete

Deletes one or more contacts, including their notes and other saved details.

Format: delete INDEX [INDEX]...

  • Supply distinct positive integers separated by spaces, in any order. Commas and ranges such as delete 1,3 and delete 1-3 are not accepted.
  • Indices refer to the filtered and sorted list displayed before deletion. Remaining contacts are renumbered afterwards; the current filter and sort order are preserved.
  • If any index is invalid or repeated, nothing is deleted. Contacts, the current view and undo/redo history remain unchanged. The error identifies the problem and, for an out-of-range index, the valid range.
  • If the displayed list is empty, use list to reveal saved contacts or add if none are saved.
  • Single-contact feedback starts with Deleted person:. Batch feedback starts with Deleted N contacts: and lists contact details with their original indices, in the order you supplied them.
  • One undo restores the whole batch; one redo deletes it again. Undo history is available only during the current session.

Examples:

  • find Betsy, then delete 1, removes the first displayed search result.
  • With at least five contacts displayed, delete 5 1 3 removes the original fifth, first and third contacts. Feedback lists them in that order; all other contacts remain.
  • With three contacts displayed, delete 1 4 rejects the whole command, including the valid selection 1.

Clearing all entries: clear

Clears all entries from UniMate.

Format: clear

Caution: clear removes all your contacts. You can bring them back with undo, but only while UniMate is still open: undo history is cleared when you close UniMate.

Undoing a change: undo

Takes back your most recent change to your contacts.

Format: undo

  1. You can undo any command that changes your contacts:

    • add, edit, delete and clear
    • tag, untag, fav and unfav
    • note and delnote

  2. Each undo takes back one command. Run it again to go further back, one change at a time. There is no limit.

    • delete 1 3 5 and clear are each taken back in a single undo

  3. UniMate tells you which change was undone.

    • Undid: Tagged person: …​
    • Undid: Deleted person: Alex Tan; …​
    • the message shows the details from when you made the change, not the details brought back. Check the contact list to see what was restored
    • for edit, the message lists the contact's full details instead of only what changed

  4. After an undo, all your contacts are shown. Any search or filter is cleared, but your sort order is kept.

    • check the contact numbers again before your next command

  5. Commands that did not change anything are skipped, and undo takes back the change before them.

    • edit with the same details, tag with a tag the contact already has, or clear on an empty list
    • commands that failed, such as adding a duplicate contact
    • commands that only show contacts, such as list, find, filter, sort, listfav, shownote, tags and help

  6. Do not type anything after undo.

    • undo 1 shows an error, and nothing is undone

  7. If there is nothing to undo, UniMate shows There is no change to undo.

  8. Undo only works while UniMate is open. Closing UniMate clears your undo history.

  9. Your contacts are saved automatically after an undo.

    • if a command showed a save error, the change was still made, so undo can take it back. See Saving the data

Examples:

  • add n/Alex Tan p/91234567 e/alex@example.com a/10 Kent Ridge Road, then undo, removes Alex Tan.
  • edit 2 p/98765432, then undo, brings back the 2nd contact's old phone number.
  • note 1 Follow up, then note 1 Project teammate, then undo, brings back the note Follow up.
  • delnote 1, then undo, brings back the deleted note.
  • delete 1 3 5, then undo, brings back all three contacts at once.
  • fav 1, then tag 2 t/Friend, then undo twice: the first undo removes the Friend tag, and the second removes the favourite.

Redoing an undone change: redo

Brings back a change you undid.

Format: redo

  1. Each redo brings back one undone change, starting with the one you undid last.

    • run redo again to bring back more, in the order you first made them
    • you can undo a redone change again

  2. UniMate tells you which change was redone, in the same way as undo.

    • Redid: Added to favourites: …​

  3. After a redo, all your contacts are shown. Any search or filter is cleared, but your sort order is kept.

  4. You can only redo until you make a new change. After a new change, such as add, delete or fav, your undone changes are gone, even if you undo the new change.

    • tag 1 t/Friend, undo, fav 2, undo, then redo brings back only the fav. The tag cannot be redone

  5. Commands rejected before changing contact data, commands that make no changes, and commands that only show contacts do not affect redo. A command that changes contact data and then fails to save can still clear redo. See Saving the data.

  6. Do not type anything after redo.

    • redo 1 shows an error, and nothing is redone

  7. If there is nothing to redo, UniMate shows There is no change to redo. An undone change cannot be redone after another change has been made.

  8. Redo only works while UniMate is open. Your contacts are saved automatically after a redo.

Examples:

  • add n/Alex Tan p/91234567 e/alex@example.com a/10 Kent Ridge Road, then undo, then redo, adds Alex Tan back.
  • edit 1 p/91234567, then undo, then redo, changes the 1st contact's phone number to 91234567 again.
  • delnote 1, then undo, then redo, deletes the note again.
  • clear, then undo, then redo, clears your contacts again.

Tip: If you undo a change by mistake, run redo straight away, before making any other change.

Exiting the program: exit

Exits the program.

Format: exit

If earlier contact changes have not been saved, exit retries saving them. If saving still fails, the window stays open with a recovery message. Fix the saving problem and run exit again. With no unsaved contact changes, exit works even when the data file is read-only.

Navigating command history

With the command box focused, press ↑ to recall the most recently submitted command. Press ↑ again to browse older commands, or ↓ to browse newer commands. After the newest command, ↓ restores the draft you were typing before browsing. At the oldest command, further ↑ presses keep that command displayed.

While browsing, a label beside the command box shows History i/N, where 1 is the oldest submission and N is the newest. Repeated identical commands occupy separate positions, so three list submissions show History 3/3, 2/3, then 1/3 as you press ↑. The label briefly pulses on every history arrow press, including ↑ at the oldest entry, even when the command text stays the same. It disappears when you return to your draft or press Enter, including a failed submission. At the draft or with empty history the label stays hidden. Prefix search uses the same absolute positions among all submissions, so its displayed numbers may skip unrelated entries.

Commands are recorded when you press Enter, including unsuccessful commands and repeated submissions. Empty input is not recorded. You can edit a recalled command and press Enter to submit it again; browsing alone does not execute commands. Edits made while browsing are not saved in the history. History is cleared when you close UniMate.

With no history, either arrow leaves your input unchanged. After the draft has been restored, further ↓ presses leave it unchanged. Recalled text places the caret at the end; the contact list and result message stay as they were until you submit a command. A successful submission clears the command box; a failed submission keeps the text for correction and can still be recalled.

For example, submit list, then find Alice. Type edit 1 m/ without pressing Enter. Press ↑ twice to see find Alice then list; press ↓ twice to return through find Alice to your draft edit 1 m/. None of these arrow presses executes a command.

For optional prefix search, type a prefix such as add (including the space), then press Alt+↑ (Option+↑ on macOS) to skip unrelated commands and recall older matching entries. Alt+↓ (Option+↓) browses newer matches and restores your original draft after the last match. Matching is case-sensitive and includes spaces; an empty prefix matches all commands. Repeated shortcut presses keep the initial prefix. At the oldest match, or when there is no match, the input stays unchanged. Alt+↓ without an active search leaves input unchanged. Editing the text starts a new prefix search from that text at the current history position. Ordinary ↑/↓ continues chronologically from the current position and ends the prefix search. Both navigation modes preserve the draft saved when you first left the end of history, and neither executes commands.

For example, submit add n/Alice a/NUS, list, add n/Bob a/NUS, then list. Type add without pressing Enter. Alt+↑ recalls add n/Bob a/NUS, then add n/Alice a/NUS; Alt+↓ recalls add n/Bob a/NUS, then restores add .

To check the position label, start a fresh session and submit list, find Alice, then list. Type li and press Alt+↑ twice: the label shows History 3/3, then History 1/3. Pressing Alt+↑ again keeps History 1/3 and pulses the label. Alt+↓ returns to History 3/3; the next Alt+↓ restores li and hides the label. These numbers count all submissions, including find Alice, rather than only the two matches. This session's command recall is separate from undo, which restores contact data.

Saving the data

UniMate automatically saves contact data after successful commands, except help. The exit command saves only when contact changes remain unsaved. You do not need to save manually.

If UniMate cannot write the data file, for example because the file or its folder is read-only, contact changes already made by the command remain inside UniMate. Instead of the usual success message, the result box shows one of these errors:

  • Could not save data to file ... due to insufficient permissions to write to the file or the folder.
  • Could not save data due to the following error: ...

Earlier release testing confirmed read-only contact-save errors on macOS, Linux and Windows. The new save and UI recovery regressions were checked on Windows.

When contact changes remain unsaved, the message also explains how to recover. For a new change, undo reverts it; after an undo, redo restores it. A failed list retry identifies earlier unsaved changes. If the current contacts already match the last saved state, no unsaved-change note is added.

Saving writes a separate temporary copy before replacing the saved file. A failure while writing that temporary copy leaves your previously saved contacts intact. The contact list and undo/redo history still reflect any changes kept in memory.

help opens without trying to save, so it remains available during a storage problem. If exit cannot save pending changes, it keeps the window open and explains that those changes still need saving. Fix the problem, then run list to retry saving or exit to save and close.

If startup reported a data-file loading error, saving contacts stays disabled for that entire session. Running list or repairing the file while UniMate remains open does not enable saving. Follow Recovery after a loading error before making changes.

Caution: A save error does not mean a contact change was cancelled. Run undo only if you want to revert that change. To keep it, fix the cause of the error, then run list to save all current contacts. Closing with the window's close button before saving discards changes since the last successful save.

Editing the data file

UniMate saves contacts in data/unimate.json, relative to the folder from which you launch it. Use cd to enter your chosen home folder before launching UniMate to keep this location predictable. Advanced users can edit that file while UniMate is closed; back it up first.

Recovery after a loading error

Caution: If the data file cannot be loaded, UniMate opens with an empty contact list and an amber warning naming the file. The original file is preserved, and saving contacts is disabled for the rest of that session, including saves attempted by list or exit.

  1. Close UniMate using the window's close button. If you entered new contacts or edits after the warning, copy any details you need manually first; those changes exist only in memory and cannot be saved in that session.
  2. Back up data/unimate.json, then repair it or restore a valid copy while UniMate is closed.
  3. Reopen UniMate from the same folder. Check that your contacts load and the recovery warning is absent before making changes. Contact saving then works normally.

Help remains available during recovery. The file is kept in place; UniMate does not create a separate recovery backup or automatically reload a file repaired while the app is still open.

A file containing only null, a null contact entry such as {"persons":[null]}, or a null tag entry such as "tags":[null] is invalid. UniMate rejects the whole file, logs the loading error, shows the recovery warning and disables contact saving. For null contact or tag entries, the logged error identifies their positions, counting from 1 in the saved arrays (not the GUI's displayed order). Follow the recovery steps above before repairing or restoring the file. A valid empty address book ({"persons":[]}) and omitted optional contact fields remain supported.

FAQ

Q: How do I transfer my data to another computer?
A: Install the same UniMate version on the other computer. Close UniMate on both computers and back up both data files. Copy data/unimate.json from the old launch folder into the new launch folder's data directory, replacing its file. Reopen UniMate and check your contacts before deleting the backup. See Editing the data file for the file location.

Q: What happens if window settings are missing or null?
A: If guiSettings is missing or null in preferences.json, UniMate uses its default window size and position. Valid saved settings are preserved, and your contacts are unaffected.

Known issues and limitations

This section lists every known issue and limitation of the current release. Each entry gives a remedy or workaround where one exists.

Window and display

  1. When using multiple screens, if you move the application to a secondary screen, and later switch to using only the primary screen, the GUI will open off-screen. The remedy is to delete the preferences.json file created by the application before running the application again.
  2. If you minimize the Help Window and then run the help command (or use the Help menu, or the keyboard shortcut F1) again, the original Help Window will remain minimized, and no new Help Window will appear. The remedy is to manually restore the minimized Help Window.
  3. Very long search or filter criteria can hide the contact list. The status text above the cards grows as it wraps, leaving little or no space for contacts in a small window. This was reproduced on Windows at 450 × 600 with find StatusProbe followed by 250 space-separated a keywords, and with a long exact-major filter. Contacts are not deleted. Run list to restore the contact list, then use a shorter search or filter.

Keyboard

  1. The message area shows no focus outline. After Ctrl+Tab moves focus to the message area, nothing on screen changes. The remedy is to press Down to check (the message scrolls if it has focus), and press Ctrl+Shift+Tab or click the command box before typing. See Using the contact list.
  2. Ctrl+Tab into the message area is standard Java behaviour, not a UniMate shortcut. UniMate handles only plain Tab and Shift+Tab. Ctrl+Tab and Ctrl+Shift+Tab work because the Java window toolkit that UniMate uses moves focus between controls with them. The route works on macOS, Linux and Windows. Clicking inside the message area also focuses it.
  3. Tabs and line breaks in pasted text are removed by the command box before submission, so pasted words can be joined. See note.
  4. Tab can skip a selected contact that has been scrolled out of view. If the list has focus and you scroll until the selected card is no longer visible, Tab may return to the command box instead of reaching that contact's expandable values. From the command box, press Tab to bring the selected contact back into view, then Tab again to focus its first expandable value.

Data and saving

  1. If saving the data file fails, contact changes already applied remain inside UniMate. The save error replaces the usual success message and explains which changes still need saving. For a change made by that command, it names redo after undo, or undo otherwise, to reverse it. To keep the changes, fix the saving problem and run list to retry. See Saving the data.
  2. If pending changes cannot be saved, exit keeps UniMate open. Fix the saving problem, then run list to retry saving or exit to save and close. help still works. With no unsaved contact changes, exit works even when the data file is read-only. Using the window's close button discards unsaved changes.

Input

  1. Some valid-looking email domains are rejected. If the last part of the domain (after the final .) contains a hyphen, it needs at least two letters or digits on one side of a hyphen. For example, a@x.y-z and a@a-b are rejected, while a@x.ab-c is accepted. The error message does not mention this rule. There is no remedy other than omitting or changing that email; see the email field rules.
  2. An extremely long email address (thousands of characters, far beyond any real address) may be accepted and saved, but UniMate then fails to start on the next launch. The remedy is to close UniMate, edit data/unimate.json to shorten or remove that email, then relaunch. Keep backups before testing unusual input.
